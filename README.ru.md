# Ядро Вектор-06Ц для Karabas Go / Mini / Mini G

[English version](README.md)

Ядро советского домашнего компьютера [Вектор-06Ц](https://ru.wikipedia.org/wiki/Вектор-06Ц) (1986) для плат семейства Karabas Go (Xilinx Spartan-6 XC6SLX25): КР580ВМ80А на 3 МГц с точными тактами ожидания оригинала, 64 КБ ОЗУ и квазидиск 256 КБ, графика 256 × 256 в 16 цветах из 256 (или 512 × 256 в 4), трёхголосый звук таймера КР580ВИ53, AY, контроллер дисковода КР1818ВГ93, вход магнитофона.

| Плата | Видео | Звук |
|---|---|---|
| Karabas Go | VGA | I2S ЦАП (PCM5102) |
| Karabas Mini | HDMI | HDMI, аналоговый выход (сигма-дельта) |
| Karabas Mini G | HDMI | HDMI, I2S ЦАП |

Файл ядра `src/vector06c.kg` — один на все три платы.

Состояние: проверено на Mini G (Загрузчик, МикроДОС с образа дискеты, дисковод B, программы, звук ВИ53). Сборки Go и Mini на плате ещё не запускались.

## Начало

1. Скопируйте `src/vector06c.kg` в корень SD-карты и создайте на ней каталог `/vector06c`. Положите туда программы (`.rom`), образы дискет (`.fdd`), образы квазидиска (`.edd`) и записи кассет (`.wav`).
2. Выберите Vector-06C в меню ядер. Загрузчик показывает свой экран: ВЕКТОР-06Ц, значок кассеты, полосы загрузки. Он ждёт магнитофон или диск.
3. Программа: откройте OSD (**Menu+Esc**), Files → ROM file (**Menu+F2**). Она сразу стартует.
4. Диск: Disks → Disk A (**Menu+F7**). Загрузчик перезапускается и читает загрузочные сектора (значок дискеты, полосы заполняются). Затем **Start** (**Menu+F11**, БЛК+ВВОД оригинала) запускает его: диск МикроДОС приходит к `A>`.

«Menu» — клавиша Windows.

## Клавиши

Раскладка — как у ядра MiSTer: клавиша Вектора на месте клавиши ПК.

| Клавиша ПК | Вектор |
|---|---|
| Esc | АР2 |
| Ctrl | УС |
| Shift | СС |
| Alt | РУС/ЛАТ |
| Tab | ТАБ |
| Backspace | ЗБ |
| Enter | ВК |
| F1 … F5 | F1 … F5 |
| F6, Home (цифровая 7) | ↖ |
| F7, PgUp (цифровая 9) | СТР |
| Delete (цифровая .) | ПС |
| `=` | `:` |
| Ctrl+F11, Shift+F11 | сброс в Загрузчик |
| Alt+F11 | запуск программы в памяти (как Start) |

Если держать УС (Ctrl) при старте Загрузчика, он очищает только экран, а не всю память.

## Файлы

- `.rom` / `.com` / `.r0m`: программа, грузится с 0100 (до 65 280 байт) при выключенном ПЗУ; память вокруг очищается, и процессор от 0000 доходит до неё.
- `.fdd`: образ дискеты, 80 дорожек × 2 стороны × 5 секторов по 1024 байта (819 200 байт; у некоторых образов 82 дорожки). Запись идёт в образ на карте.
- `.edd`: квазидиск, до 256 КБ (4 страницы по 64 КБ).
- `.wav`: запись кассеты, PCM 8 или 16 бит, моно или стерео (левый канал), любая частота, до 2 МБ (22 кГц 8 бит моно — полторы минуты). Загрузчик грузит из неё как с магнитофона; программы, читающие ленту, — тоже.
- Загрузчик: `src/roms/boot.rom`, «Загрузчик» vector06cc (2 КБ, тот же, что `bios.mif` ядра MiSTer).

## Где взять программы

- Демо и интро Вячеслава Славинского (svofski), автора vector06cc, с готовыми `.rom`: [v06c-timersound](https://github.com/svofski/v06c-timersound) (`release/timersound.rom`, есть и `.wav`), [v06c-floppy](https://github.com/svofski/v06c-floppy) (`release/blksbr.rom`).
- Системная дискета МикроДОС: `ryba.fdd` из [v06c-badapple](https://github.com/svofski/v06c-badapple).
- Инструменты: [bin2wav](https://github.com/svofski/bin2wav) (двоичный файл в `.wav` кассеты), [v06c-fddutil](https://github.com/svofski/v06c-fddutil) (образы дискет), эмуляторы [vector06sdl](https://github.com/svofski/vector06sdl) и [vector06js](https://github.com/svofski/vector06js).

## Как устроено ядро

Машина — ядро MiSTer Sorgelig ([Vector-06C_MiSTer](https://github.com/MiSTer-devel/Vector-06C_MiSTer)), само основанное на vector06cc, приведённое к правилам ядер Karabas:

- один клок 48 МГц с enable: процессор (потактовая модель КР580ВМ80А Vslav) на 3 МГц ждёт своего слота 4-тактного цикла памяти, как в оригинале (кадр — 59 904 такта, проверено в симуляции);
- память — SRAM платы: основные 64 КБ, квазидиск, Загрузчик, образы дискет; экран (8000–FFFF) ещё и копируется в блочную память, видео никогда не ждёт;
- видео сохраняет кадр Вектора: 768 × 312 пикселей по 12 МГц, каждая строка выводится дважды как 576p с 624 строками (50,08 Гц, 31,25 кГц как у CEA 576p), видно 640 × 576. Без буфера кадра: ни один кадр не пропускается и не повторяется;
- дисковод: один КР1818ВГ93 на оба привода (как в оригинале), образы кэшируются в SRAM;
- все файлы идут через прошивку платы (пункты OSD): soft-CPU в ядре нет.

Исходники: `src/rtl/v06c/` (машина), `src/rtl/karabas_*_top.v` (платы: Go и Mini делаются из верха Mini G скриптом `src/tools/mktops.py`), `docs/PLAN.md` и `docs/HARDWARE.md` (план, порты, память, видео).

## Сборка

ISE 14.7. `cd src && make` собирает все три платы и `vector06c.kg`; `make minig` (или `go`, `mini`) — одну плату, `make minig-report` — её размер и тайминги. `make v06c-xst` синтезирует одну машину. Клонируйте с `--recursive` (подмодуль `modules`). Исходники upstream для справки: `tools/fetch_upstream.sh`.

## Тесты

`src/sim/run.sh` (verilator, около 3 минут): Загрузчик и кадровое прерывание, программа с 0100 на 3 и 6 МГц, такты ожидания (цикл между двумя прерываниями), квазидиск, запись на дискету, AY, лента из `.wav`. С `FDD=<образ МикроДОС .fdd>` ещё загружает МикроДОС (около 3 минут сверху).
